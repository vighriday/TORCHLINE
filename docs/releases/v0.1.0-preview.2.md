# v0.1.0-preview.2

One continuing Ark, one integrated source baseline. This development preview brings the final ten-screen design, Minecraft LIVEWIRE, recovery fixes and independent QA coverage together on main.

## What changed

- The complete final design now presents actual saved gameplay, history, lasting damage, account setup and read-only OBS. The Ark, cockpit and Minecraft scene share the same working application.
- LIVEWIRE lets chat choose a system at risk before a streamer attempt. A locked, streamer-confirmed result applies one bounded consequence to the persistent Ark. It remains default-off; the Minecraft scene is illustrative, not telemetry.
- Chapter controls retain cooperative challenges, investigation, allocation and manual/custom clocks. A late refresh no longer overwrites an unsaved timing selection.
- Recovery work separates optional bot output from incoming gameplay, bounds database operations and preserves replay/backup behavior.
- Two missed adversarial PostgreSQL tests now verify competing mutations and duplicate receiver accepts. The obsolete UI-LAB prototype is preserved separately, without reintroducing its screens or fixture server.
- The README uses current, visible app captures and real browser-recorded Ark/Minecraft animations.

## Evidence and limits

Automated verification includes engine/API/database tests, real PostgreSQL concurrency checks, browser gameplay/recovery/layout/rendering journeys, generated proof consistency and restricted-container smoke. Exact-source Verify must pass before this prerelease is published. [Workflow](https://github.com/vighriday/TORCHLINE/actions/workflows/verify.yml) · [Consolidation evidence](https://github.com/vighriday/TORCHLINE/blob/v0.1.0-preview.2/docs/reports/2026-10-30-main-consolidation.md).

The final-design cutover has native OBS rendering, refresh and scoped-access evidence in saved practice. Genuine incoming query chat has been observed, but a real viewer command changing the saved Ark, native raid transfer, sustained broadcast performance and permanent hosting remain open. Provider-accepted invisible bot replies are not claimed as visible delivery. No deployment or new Twitch acceptance is implied by merging source.
