## Deliberate first-slice limits and next work

- Automatic phase deadlines, bounded allocation, meaningful investigation, pause/park/restart recovery and explicit captain commitment are implemented. Per-account cooldown/flood policies, long-outage fencing and broader load/soak evidence remain hardening work.
- Gameplay chat supports `!scan`, `!route`, `!patch`, `!vote`, `!inspect` and `!allocate`. Query replies for `!status`/`!history` are implemented and fixture-tested; genuine delivery remains pending. Proactive announcements remain future work.
- Early ingress binds a window under the world lock. Close/pause refuses while accepted input is pending. Per-phase/ballot tables and finer write partitioning are needed before claiming the planned large-chat throughput.
- A PostgreSQL session lease fences one worker per database/schema/mode. Persisted retries, eighth-failure quarantine, private diagnostics and current-window creator recovery are implemented. Cross-instance SSE fan-out and scheduled retention remain future hardening.
- Reconciliation now paginates provider records, serializes per channel, runs on startup/authorization and bounded periodic batches, and retires tracked subscriptions for obsolete configurations. Untested public-provider behavior, transient-error handling and broader network scale still require further evidence.
- Current event replay reconstructs the game from accepted commands under immutable rules and checks stored effects. Hosting/custody revisions have their own transaction/audit records; they do not mutate game sequence numbers.
- Load/soak targets, backup restore, deployment rollback, actual OBS frame time, final accessibility/usability playtesting, owner visual/usability acceptance remain unverified or unfinished. The supplied Claude Design surfaces are integrated within the current presentation contract.
- The HTTP server binds loopback by default. This is a local functional slice, not a claim of production readiness.

The next priority is restored HTTPS plus genuine chat/bot/OBS/native-raid acceptance, alongside load/input hardening and owner visual/usability review. Authentic raid custody remains the defining technical milestone; a simulator does not satisfy it.
