## Public-facing routes and authority

All route registrations in [app.ts](../../apps/server/src/app.ts) were traced. Default client-supplied roles/actor IDs do not authorize a live mutation. POST origin/custom-header checks apply except the independently authenticated EventSub gateway. Expected revision, command identity, current channel/slot, mode and SQL locks add mutation checks after session authentication.

This is bounded evidence, not a claim that all possible attacks were exhausted. HMAC, CSRF and a dependency audit do not supply edge capacity or data-retention policy.

## Test quality and missing coverage

| Evidence family | What it actually establishes | What it does not establish |
| --- | --- | --- |
| Engine and cooperation | Deterministic transitions/replay, mechanical rewards, no farming, forecast equality, allocation caps/overkill/identity, v2 branch witnesses and some v3 endings. | Exhaustive current combined season, enjoyable difficulty, people cooperating or actual Twitch input. Tests that directly alter state exercise defensive arithmetic, not reachable gameplay witnesses. |
| PostgreSQL storage/records | Same-client transactions, serialized competing claims/revisions, proof consumption, real constraints, privacy/cursors, persisted park/pause/reload. | Every crash point/deadlock/interleaving or managed-DB behavior. No instrumentation kills the process at every statement in a custody transaction. |
| Episode / ingress recovery | Duplicate-safe close, accepted-before-cutoff drain, explicit park/restart/offline pause, worker fencing, retries/quarantine. | Chat-subscription loss pausing (new failing probe), prolonged DB lock behavior, all current-rule timing/choice combinations or long deployed outage. |
| OAuth/EventSub/bot fixture | Correct client-side request shapes, raw-byte signatures, local authority/dedup/order, scopes/role logic, provider drops/uncertain sends, lifecycle refresh races and full contract handoff. | Real provider accepts every request shape, genuine chat/reply appearance, genuine raid delivery, or Twitch notification timing. `providerFixture` calls the local challenge route itself. |
| Browser | Real built React and production assets, canonical SQL game controls, simulated custody, responsive keyboard/motion/graphics failure, actual changing WebGL pixels. | Installed OBS, hardware/mobile Twitch performance, reader comprehension, all color contrast/focus announcements. One fresh onboarding failure is real even with green remote CI. |
| 50,000-row history fixture | Query planner chooses partial public-tail index and results stay bounded. | 50,000 engine transitions, large state write cost, canonical replay or audience throughput. |
| Backup/process/container | Native authenticated archive/restore with one gameplay fixture; actual process replacement; Linux CI restricted image/shutdown. | Off-machine durability, restore/cutover of today's live Ark, provider migration/rollback, RPO/RTO or a source that stays available through judging. |
| New audit load probes | 10k unique pure-engine ballots; four-feed idle query cost; one 500-message signed synthetic burst/admission/drain. | Planned two-world 10-minute baseline, ten-world five-minute stress plus spike, full 10k PostgreSQL ballot correctness, hour soak, native OBS under load. All remain release gates. |

The suite has meaningful invariant/failure tests rather than only shallow mocks. Its blind spots are integration composition, prolonged conditions and external evidence. A passing provider fixture cannot close PR03/PR05; a historically green browser suite cannot override a fresh failed run.
