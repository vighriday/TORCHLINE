# LIVEWIRE v0 implementation and release assessment

October 30, 2026. Feature branch: `feat/livewire-v0`, isolated under `.local/worktrees/livewire-v0`, based on `89fa019`. The original `feat/gameplay-foundation` worktree, published release/tag and real Ark remain separate. Private planning inputs and access links are not published.

**Outcome:** a complete database-backed mission slice now connects ordinary gameplay commitments to the same Ark engine, physical condition and history. It works through the functional captain screen and transparent OBS dock. It is default-off and **not deployed to the real Twitch world**. Genuine chat-driven gameplay and native raid acceptance remain open; this is not a production-ready release declaration.

## What works

The connected current captain opens a mission between chapters, using a preset and bounded plain-text game/attempt label. Chat chooses navigation, hull or life support through `!stake` or the context-sensitive `!vote` alias. A durable, explicit lock freezes the target, exact effects, aggregate participation, channel, author, time and policy before the attempt. The captain then confirms one **streamer-attested** result. The engine changes the canonical Ark, records physical marks and a causal event, and publishes the saved result to the existing projections.

With zero votes, the captain explicitly chooses a labeled solo target. Latest valid ballots replace earlier ones; provider timestamps retain nanosecond ordering, followed by a delivery-ID tie-break. Tied systems use the published navigation → hull → life-support order. Lost/sealed systems are unavailable.

Opening irrevocably consumes one supply and that chapter boundary's allowance. There are at most five openings in a season, across all hosts. Success restores up to three points; failure removes up to six, stopping at one. No passenger, power, supply or obligation rewards are invented. Cancellation/expiry does not refund the allowance. Maximum gross gain is therefore 15 repair points. Witnesses show repairs can avert an otherwise fatal later oxygen cost while still leaving a costly partial ending; colony, partial and wreck remain reachable in tested full-season policies.

Selection has 45 seconds to lock; a locked attempt has two hours to be attested. A timeout never invents an outcome. Open selection pauses across restart, chat loss, disconnect and applicable offline notification, then requires explicit resume with saved remaining time. Pre-resume messages are rejected. Unresolved missions block chapter commands, parking and handoff preparation. Closed mission damage and spent allowances persist through a consented **simulated** custody transfer; former-host commands fail and the receiver cannot renew the same boundary's allowance.

## Authority and privacy review

| Capability | Intended authority and executed checks |
| --- | --- |
| `POST /api/worlds/:id/livewire` | Connected current custodian, correct mode and active slot; channel/world locks, optimistic revision, request hash/idempotency. Other creator, overlay-only cookie, foreign origin and malformed effect fields fail |
| Existing Ark command endpoint | Internal mission commands/tallies are excluded from its public schema; clients cannot submit engine-derived gains or fabricated lock counts |
| Twitch participation | Existing raw-byte HMAC, exact subscription/condition and bot-identity checks precede routing. Bot-authored commands and Shared Chat mirrors do not count. Delivery/message deduplication, cutoff, admission and 10,000-participant limits apply |
| Practice participation | Creator-authenticated simulation only; existing live-mode simulation denial remains covered |
| Overlay | Existing path-scoped revocable read capability; compact/auto affect layout only. No host buttons or OBS control permission; actor/channel author fields and voter roster omitted |
| Operator verifier | Local private configuration and read-only repeatable-read transaction. Missing candidate tables report `not_deployed`; simulation alone cannot pass the genuine-input join |

The built feature assets, Git objects/index and logs were checked against 15 current private fingerprints, with ten selected real public responses checked separately. No secret matched. This is the stated scan scope, not a universal secrecy certification. No private input, environment file, overlay URL or session export is staged. No new Twitch scopes, account-role changes, actual Twitch chat sends, cloud purchases or public submission were performed.

## Release decision and remaining work

**Safe next step:** review this isolated candidate and activate it on an intended staging/live candidate behind its flag. Keep the original release intact until that decision. The implementation is suitable for controlled playtesting; a general production-ready claim is premature.

1. **P1 — genuine loop:** the owner chooses the current chapter consequence, reaches a ready boundary, opens a reviewed candidate mission, sends one displayed legal command in actual chat, locks before their real attempt and attests its result. Observe actual OBS and run the read-only verifier. No new bot account or app registration is needed.
2. **P1 — deployment:** select/authorize host account, region/budget and remote backup destination; run migration/rollback, HTTPS/SSE, restart and clean-host restore checks. Restricted-image CI is not a managed deployment.
3. **P1 — native handoff:** a second consenting broadcaster later authorizes/opts in. Perform a real prepared native raid and explicit acceptance, checking inherited condition/history and former-host denial. Keep hriday_29 exclusively as bot.
4. **P1 — inherited audit debt:** A07's legacy participant-map/feed query amplification and A11's global HTTP/SSE ordering/world-reassignment concerns remain open. LIVEWIRE avoids a new voter map and fixes fragment recovery; that does not close those wider findings. A08's broader deployed limits/retention/telemetry and A09's exhaustive current cooperation balance also remain.
5. **Submission:** preserve a working source/deployment, capture truthful footage and the actual Codex session ID, finish the video/entry/access/confirmation checklist. Do not wait for other proposed arms or claim simulated raid footage as native proof. Use the existing [submission plan](../planning/hackathon.md).

Do not add more gameplay arms before these acceptance and reliability gates. Other than the necessary account-owned choices, real gaming/OBS observation and a second broadcaster for the raid, engineering and reproducible testing can continue independently.
