# 0016 — Reproducible live ingress without credential exposure

Accepted 2026-10-27. Freeze gameplay/design while preparing a release candidate. Keep the existing Twitch app, creator/bot grants, webhook transport and PostgreSQL authority.

**October 28 incident:** Windows Defender quarantined the third-party ngrok agent binary (not TORCHLINE code) as `Trojan:Win32/Kepavll!rfn`; it was not restored/exempted and stays unused. Live tests use ngrok's SSH reverse tunnel instead: `live:ssh:prepare` creates a dedicated ignored project key and pins the India server's RSA fingerprint from official HTTPS documentation. `live:ssh` uses installed OpenSSH with project-only config/known-hosts/key, no Twitch or token environment, strict host checks, keepalive and bounded reconnect. It exposes only the existing live port; no inspection interface exists.

**October 28 restoration:** after owner public-key registration, SSH authenticated and restored the same current origin. Real public health/readiness/authority denials and ten selected response secret scans pass. Chromium positively verifies cookie exchange/read-only SSE/private-field omission/mutation denial, then removes its temporary grant. There is no live Ark yet, and no native OBS evidence is implied. All three exact provider subscriptions and existing real grants still validate; old signed challenges remain historical. Twitch sign-in returned `redirect_mismatch` to the old hostname; the current outbound redirect was verified correct, so the owner must save it in the existing app's console and start fresh.

The original C1–C13 review remains applicable: engine/episode/custody/identity/read authority is unchanged. Operational verification adds an ignored timestamp baseline (aggregate new signed delivery → persisted action/native accepted reply/linked raid transfer counts), all-page provider diagnostics and a five-minute read-only overlay probe. That probe neither rotates ordinary grants nor creates a world, sends messages or changes custody; positive public Chromium acceptance now passes but cannot prove native OBS. See [release authority review](../reviews/2026-10-28-release-authority.md).

The owner's newly configured ngrok credential was valid but the old hostname belonged to another account (the real agent returned ERR_NGROK_320). Use that account's assigned development hostname rather than requesting another secret or buying a domain. `live:tunnel` passes the authtoken only through the child environment, disables request inspection, binds the agent API to loopback and suppresses raw agent diagnostics. It passes no Twitch/database credentials to ngrok. `--assigned-domain` discovers the actual HTTPS forwarding origin. `live:origin` first identifies the real live service, then atomically changes only the ignored environment's public origin and exact OAuth redirect. Restart the live service afterward; its existing reconciliation installs/retire subscriptions for the new callback.

The alternative is restoring credentials for the old account or deploying permanent hosting immediately. The assigned development endpoint removes the current callback blocker without changing accounts, incurring hosting spend or claiming always-on availability. Permanent hosting remains a separate reviewed release operation. The Twitch console's exact OAuth redirect still requires the owner; there is no assumed application-management permission in the creator grant.
