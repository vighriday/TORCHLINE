# Twitch account setup and verification

Status: external accounts are not yet configured, as confirmed by the owner on 2026-10-26. Do not paste client secrets, passwords or tokens into chat or Git.

1. Sign in at the [developer console](https://dev.twitch.tv/console/apps) using the app owner's account. Verify email and enable 2FA. Register TORCHLINE as a confidential application in the appropriate game/application integration category.
2. Register exactly `http://localhost:3000/auth/twitch/callback` for local OAuth. Generate the client secret and keep it private. [Official registration requirements](https://dev.twitch.tv/docs/authentication/register-app/)
3. Run the local setup in the README. `pnpm db:up` creates an ignored `.env` with generated local database/session/encryption secrets. Edit this existing file; do not replace it with placeholder values from `.env.example`.
4. Run `pnpm live:prepare` to create a separate local `torchline_live` database and ignored `.env.live` with independent keys. Add `TWITCH_CLIENT_ID` and `TWITCH_CLIENT_SECRET` to **`.env.live`**; its redirect URI and EventSub key are initialized. Run `pnpm db:migrate:live`, stop the simulation server if running, then run `pnpm start:live`. `pnpm twitch:doctor:live` prints configuration presence only. Preparation refuses to overwrite an existing live environment file.
5. Use the homepage's creator connection link. For the separate bot account, open a private browser session at the homepage, enter the operator `BOT_SETUP_SECRET` from `.env.live` into the bot setup field and authorize the bot. The bot flow requests `user:read:chat user:write:chat user:bot`; the creator flow requests `channel:bot`. The operator secret is an app setup credential, not a Twitch password. All grants use this same client.
6. For the public callback spike, use a public HTTPS tunnel/host forwarding to the live server. Change `.env.live` `PUBLIC_BASE_URL` and `TWITCH_REDIRECT_URI` to that origin, add the exact new redirect in the console, restart and reconnect through that origin. Set `HOST=0.0.0.0` only if the hosting/tunnel arrangement requires it. A localhost callback can prove OAuth but cannot receive Twitch HTTPS webhooks directly. No tunnel or hosting is provisioned yet.
7. Connect the creator, authorize the bot, verify token identities/scopes, opt into incoming worlds and reconcile subscriptions. Confirm the public callback challenge and receive a genuine chat command before calling chat integration verified.
8. Arrange two consenting live broadcasters, check target raid settings, prepare a handoff, perform the native Twitch raid, and accept on the target. Preserve authentic proof metadata and state continuity without secrets. Simulation is never evidence of this milestone.

Implementation status and actual verification results are maintained in [implementation status](../planning/implementation-status.md). Do not assume every setup step is implemented merely because it is listed here. Bot/creator scopes and token types follow [Twitch's cloud-bot documentation](https://dev.twitch.tv/docs/chat/authenticating/).
