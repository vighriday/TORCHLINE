## Rebuild

Use the repository's Node 24/pnpm environment and installed Playwright Chromium bundle. The capture pipeline is verified on this Windows workspace; optional documentation tooling is outside application/runtime dependencies. Python regeneration requires Pillow and fontTools as listed in [the documentation requirements](../../scripts/readme/requirements.txt).

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = '.local/browsers'
pnpm exec playwright install chromium --only-shell
python -m pip install -r scripts/readme/requirements.txt
node scripts/readme/export-proof.ts
node scripts/readme/capture-model.ts
python scripts/readme/design-assets.py
node --env-file=.env scripts/readme/record-gameplay.ts
node scripts/readme/capture-frames.ts
python scripts/readme/encode-motion.py
```

Recording needs the configured local simulation PostgreSQL database and the current production browser build. It creates/drops a disposable schema and binds an isolated app on port 3102. Recorded phase timestamps select actual gameplay instead of guessing from total video length. Model capture uses an ignored Vite bundle and temporary localhost port 3105, then shuts it down. Frame conversion uses Playwright's existing FFmpeg executable; no new native download is needed. Rebuilding artwork can vary across GPUs; canonical JSON/CSV proof is deterministic and checked separately.

Review every selected frame before staging. GIFs are bounded to 5 MB each; the model stays below GitHub's documented 10 MB viewer ceiling. The README remains useful without animation: full-resolution stills, alt text and native Markdown explain the same story. The standalone SVG motion source can be reused in a normal SVG-capable browser; animation on GitHub's own SVG viewer is not promised.
